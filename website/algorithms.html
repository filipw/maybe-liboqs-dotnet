About this reference

Each entry below corresponds to a value on one of the two algorithm enumerations in the library. Availability depends on the build of liboqs that the package carries and on the platform, as noted on the overview page, so an entry that appears here may report as disabled at runtime. The IsEnabled() method on each enumeration value is the reliable way to check before use.

Security levels follow the categories defined by NIST for the standardisation process. They are summarised at the foot of this page.

Part 1

Key encapsulation mechanisms

A key encapsulation mechanism lets two parties derive a shared secret. The families below differ in the hard problem they rest on, which in turn affects key and ciphertext sizes and performance.

1.1

ML-KEM and Kyber

ML-KEM is the NIST standard derived from CRYSTALS-Kyber, and Kyber is the earlier submission from which it was developed. Both are lattice-based.

1.4

FrodoKEM

FrodoKEM is a conservative lattice scheme built on plain learning-with-errors, without the ring structure that the Kyber and NTRU families use. Each parameter set is offered with an AES or a SHAKE matrix generator. The library exposes both the standard salted form and the ephemeral eFrodoKEM form intended for single-use key pairs.

Part 2

Digital signature schemes

A signature scheme allows a private key holder to produce a value over a message that anyone with the public key can verify. As with the mechanisms above, the families differ in the assumption they rely on and in the trade-off between key size, signature size and speed.

2.1

Lattice signatures

ML-DSA is the NIST standard derived from CRYSTALS-Dilithium. Falcon is a second lattice-based standard, with smaller signatures but a more intricate implementation; its padded variants produce signatures of a fixed length.

Falcon-padded-1024Falcon, paddedLevel 5
2.2

Hash-based signatures

SLH-DSA is the NIST standard derived from SPHINCS+. Its security rests only on the properties of a hash function, which makes it conservative, at the cost of larger signatures. Each parameter set selects a hash family, SHA-2 or SHAKE, a security level, and a small or fast trade-off, denoted s and f.

SNOVA and MQOM

SNOVA is exposed across twelve parameter sets spanning the three security levels. MQOM is exposed across twelve parameter sets, in GF(16) fast and short trade-offs at each level. As noted on the overview page, the MQOM family is disabled on Windows in the bundled release and is available on Linux and macOS.

Notes

Security levels

The levels referred to throughout this page are the categories NIST defined for the standardisation process. They express the computational effort an attack is expected to require, relative to well-understood symmetric primitives.

LevelComparable effort
Level 1At least as hard as a key search on AES-128
Level 3At least as hard as a key search on AES-192
Level 5At least as hard as a key search on AES-256
